# AutoEQ Storm Research CI

## Purpose

Make the Storm research loop reproducible on a clean GitHub Actions runner without changing production solver behavior.

The workflow `.github/workflows/autoeq-storm-research.yml` has two layers:

1. **static-verify** runs automatically on every push to `research/storm-diagnosis-20260910`;
2. **scientific-replay** runs only when a pinned frozen-input bundle is available.

The static layer does not depend on legacy local `/tmp` state.

## Frozen legacy input bundle

The accepted 2026-09-08 recovery work left five required inputs outside Git under:

`/tmp/autoeq-capacity-recovery-20260908`

They were never uploaded as a durable repository artifact, so the exact historical bytes cannot be recovered from Git alone.

The required bundle is exactly:

- `OracleReferenceSnapshotV1.json`
- `mp-seeds/titan-to-storm-teacher-student.json`
- `mp-seeds/titan-to-u12t-teacher-student.json`
- `mp-seeds/titan-to-trio-teacher-student.json`
- `same-runtime-tournament/tournament-report.json`

The snapshot and same-runtime tournament are additionally pinned to SHA-256 values independently recorded in the accepted recovery report.

## One-time bootstrap

On the machine that still contains the accepted legacy freeze:

```bash
pnpm --filter @autoeq-workbench/core research:storm-frozen-inputs -- \
  pack \
  --source-root /tmp/autoeq-capacity-recovery-20260908 \
  --out /tmp/autoeq-storm-frozen-inputs-v1

tar -C /tmp/autoeq-storm-frozen-inputs-v1 \
  -czf /tmp/autoeq-storm-frozen-inputs-v1.tar.gz .
```

The pack command copies only the five declared inputs, writes `manifest.json`, computes SHA-256 for every file, validates the independently pinned hashes, and prints the manifest SHA-256.

Upload the archive once to a durable GitHub Release, for example:

```bash
gh release create autoeq-storm-frozen-inputs-v1 \
  /tmp/autoeq-storm-frozen-inputs-v1.tar.gz \
  --title "AutoEQ Storm frozen research inputs v1" \
  --notes "Immutable bootstrap bundle for reproducible Storm research CI."
```

Then configure repository variables:

- `AUTOEQ_STORM_INPUT_RELEASE_TAG=autoeq-storm-frozen-inputs-v1`
- `AUTOEQ_STORM_INPUT_MANIFEST_SHA256=<manifest-sha256 printed by pack>`

The release tag and manifest hash may also be supplied manually through workflow dispatch.

The CI does not silently reconstruct, substitute, or refresh missing historical inputs.

## Runtime contract

Campaign runners resolve legacy capacity-recovery inputs through:

`AUTOEQ_CAPACITY_RECOVERY_ROOT`

If unset, local research retains the historical default:

`/tmp/autoeq-capacity-recovery-20260908`

CI sets it to the verified downloaded bundle.

No product solver source is changed by this infrastructure.

## Replay evidence

Every successful scientific replay uploads:

- the exact frozen-input manifest;
- the generated campaign report;
- the generated Markdown results;
- replay provenance containing repository SHA, workflow run ID, campaign, and frozen-input release tag.

The workflow also fails if replay modifies `packages/core/src`, `apps`, or `vendor`.

## Current boundary

This infrastructure makes the research environment reproducible after one bootstrap of the exact historical bytes. It intentionally does not claim that the old local recovery artifacts can be regenerated byte-identically from Git history alone.
